# Mini NPU Simulator

숫자로 표현한 그림과 필터를 같은 위치끼리 곱하고 더해 Cross(십자가)와 X를 판별하는 Python 콘솔 프로그램입니다.
외부 라이브러리를 사용하지 않습니다. 실제 NPU 하드웨어나 병렬 실행을 구현한 프로그램은 아니며 MAC 원리를 CPU에서 학습합니다.

## 1. 실행 방법

- Python 3.8 이상이 필요합니다.
- 이 폴더를 VS Code의 **파일 → 폴더 열기**로 엽니다.
- **터미널 → 새 터미널**을 열고 다음 명령어를 실행합니다.

```powershell
python main.py
```

`1`은 사용자 입력, `2`는 data.json 분석, `0`은 종료입니다.
한 모드가 끝나면 프로그램이 종료됩니다. 다른 모드는 다시 실행해서 선택하세요.
`>>>`는 Python 대화형 창입니다. 실행 명령은 `PS ...>`가 보이는 터미널에 입력하세요.

바로 실행할 수도 있습니다.

```powershell
python main.py --mode manual
python main.py --mode json
python main.py --mode json --repeats 1000
python main.py --mode json --data teacher_data.json
```

`--data`를 생략하면 main.py와 같은 폴더의 data.json을 읽습니다.
상대 경로를 직접 지정하면 터미널의 현재 폴더를 기준으로 찾습니다.
반복 측정 기본값은 1,000회이며, 10회 미만은 허용하지 않습니다.

## 2. 사용자 입력 예시

1번 모드에서 아래 내용을 **한 줄씩** 입력합니다.

필터 A:

```text
0 1 0
1 1 1
0 1 0
```

필터 B:

```text
1 0 1
0 1 0
1 0 1
```

입력 패턴:

```text
1 0 1
0 1 0
1 0 1
```

예상 결과는 A 점수 1, B 점수 5, 판정 B입니다. 연산 시간은 실행할 때마다 달라집니다.
각 배열은 정확히 3행을 입력받습니다. 잘못된 열 개수, 문자, 빈 입력, NaN/Infinity는 해당 행을 재입력받습니다.
필터의 ‘저장 확인’은 실행 중 메모리에 보관했다는 뜻이며, 사용자 입력을 JSON 파일에 기록하지는 않습니다.
Ctrl+C 또는 입력 종료(EOF)가 발생하면 안내 후 종료합니다.

수업에서 제공한 실제 data.json은 이번 요청에 첨부되지 않았습니다.
함께 제공하는 파일은 예제이며, 실제 수업 데이터로 교체하면 그 데이터의 결과가 출력됩니다.

## 4. JSON 스키마

filters는 size_5, size_13, size_25 그룹을 가집니다. 각 그룹 안에는 cross와 x 필터를 둡니다.
patterns는 size_{N}_{idx} 키를 가지며, 각 값은 input과 expected를 포함합니다.

```text
{
  "filters": {
    "size_5":  {"cross": 5×5 숫자 배열, "x": 5×5 숫자 배열},
    "size_13": {"cross": 13×13 숫자 배열, "x": 13×13 숫자 배열},
    "size_25": {"cross": 25×25 숫자 배열, "x": 25×25 숫자 배열}
  },
  "patterns": {
    "size_5_1": {"input": 5×5 숫자 배열, "expected": "+"}
  }
}
```

위 블록은 구조 설명용이고 그대로 붙여 넣는 유효한 JSON은 아닙니다. 실제 data.json을 참고하세요.
키에서 N을 추출해 해당 크기의 필터를 사용하며, 배열의 모든 행과 열 개수를 검사합니다.
정수와 유한한 실수를 허용하고 bool, 문자열, NaN, Infinity는 거부합니다.
필터에 오류가 있으면 그 필터를 쓰는 케이스를 FAIL로 기록하고 다른 크기의 케이스는 계속 분석합니다.
JSON 자체가 손상되거나 patterns 전체가 잘못되면 케이스 분석을 시작할 수 없다는 메시지를 출력합니다.

## 5. 구현 요약

### MAC

```python
total = 0.0
for row in range(len(pattern)):
    for column in range(len(pattern)):
        total += pattern[row][column] * kernel[row][column]
```

같은 위치의 값끼리 곱해 누적합니다. `matrix[row][column]`으로 특정 위치를 읽거나 변경할 수 있습니다.
이 점수는 가중 내적이며 모든 그림에 대해 완전한 모양 인식을 보장하지는 않습니다.

### 라벨 정규화

앞뒤 공백을 제거하고 대소문자를 통일한 뒤 `+`와 `cross`는 Cross, `x`는 X로 바꿉니다.
filter 키와 expected 양쪽에 적용합니다. 모르는 라벨과 정규화 후 중복된 필터 키는 오류입니다.

### 동점 정책

`abs(score_a - score_b) < 1e-9`이면 UNDECIDED입니다.
차이가 정확히 1e-9이면 동점이 아니며, 상대 허용오차는 적용하지 않습니다.
UNDECIDED는 Cross/X expected와 일치하지 않으므로 FAIL입니다. 억지로 한 라벨을 선택하지 않습니다.
연산 결과가 무한대나 NaN이 되면 수치 오류로 처리합니다.

### 결과 집계

정상 판정, 동점, 잘못된 케이스를 모두 케이스 수에 포함합니다.
총 테스트 수 = 통과 수 + 실패 수이며, 실패 케이스의 식별자와 이유를 마지막에 다시 출력합니다.
필터 그룹 오류는 별도 표시하며 케이스 총수에 추가하지 않습니다.
FAIL 또는 필터 오류가 있으면 프로세스 종료 코드는 1, 모두 통과하면 0입니다.
예제 데이터의 종료 코드 1은 의도적 오류를 보고한 결과이며 프로그램 충돌을 뜻하지 않습니다.

## 6. 결과 리포트

### 실제 예제 실행 결과와 실패 원인 분석

1. 제공한 예제 data.json 실행 결과는 총 12개, PASS 9개, FAIL 3개입니다.
2. 5×5, 13×13, 25×25마다 Cross, X, 가중 Cross의 정상 사례를 3개씩 구성했습니다.
3. 정상 Cross와 X 사례는 라벨 정규화 후 expected와 판정이 일치해 통과했습니다.
4. 0.1을 곱한 가중 Cross도 float 데이터로 연산하며 올바르게 판정했습니다.
5. size_13_4는 모든 입력이 0이어서 두 필터 점수가 모두 0입니다.
6. 이 케이스는 epsilon 정책에 따라 UNDECIDED이고 expected X와 달라 FAIL입니다.
7. 동점 FAIL은 로직이 멈춘 오류가 아니라 정해진 비교 정책을 지킨 결과입니다.
8. size_5_4는 5×5 키에 2×2 입력을 넣어 크기 검증에서 FAIL입니다.
9. 이것은 데이터/스키마 오류이며 MAC 연산을 시작하기 전에 발견됩니다.
10. size_25_4는 expected를 triangle로 지정해 알 수 없는 라벨 오류로 FAIL입니다.
11. 이 역시 잘못된 데이터 라벨 문제로, Cross나 X로 임의 변경하지 않고 사유를 남깁니다.
12. 각 오류를 케이스별로 격리했기 때문에 나머지 정상 9개는 계속 분석됩니다.
13. 0.9와 0.8999999999999999처럼 표현 오차만 있는 점수는 epsilon으로 동점 처리합니다.
14. 단순히 문자열 +와 Cross를 비교했다면 오답이 될 수 있지만 정규화로 불필요한 실패를 방지했습니다.
15. 모든 실제 데이터가 통과하더라도 정규화와 허용오차 정책을 유지해야 재현 가능한 판정이 됩니다.
16. 실제 수업 데이터를 사용하면 실패 수가 달라질 수 있으며, 이 리포트의 12개 결과는 예제에만 해당합니다.

### 실제 성능 측정

측정 환경: Python 3.15.0 / Windows 11. 각 크기·방식별 1,000회, 워밍업 10회.
아래 값은 제작 시 실제 측정값이며 사용자의 컴퓨터에서는 달라집니다.

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | MAC 횟수(N²) | 2D/1D 시간비 |
|---|---:|---:|---:|---:|
| 3×3 | 0.000492 | 0.000302 | 9 | 1.63 |
| 5×5 | 0.000965 | 0.000604 | 25 | 1.60 |
| 13×13 | 0.005206 | 0.003605 | 169 | 1.44 |
| 25×25 | 0.017496 | 0.013279 | 625 | 1.32 |

### 시간·공간 복잡도와 측정 해석

1. N×N 배열의 모든 칸을 한 번씩 방문하므로 한 필터의 시간 복잡도는 O(N²)입니다.
2. 바깥 반복문 N회마다 안쪽 반복문을 N회 실행해 총 N²번 누적합니다.
3. 3×3, 5×5, 13×13, 25×25의 MAC 횟수는 각각 9, 25, 169, 625입니다.
4. N²는 MAC 횟수이며 곱셈과 덧셈을 각각 세면 대략 2N²개의 산술 연산입니다.
5. 두 필터로 판정하면 2N² MAC이 필요하지만 상수 2를 제외한 복잡도는 여전히 O(N²)입니다.
6. 패턴 M개를 같은 크기로 분석하면 O(MN²)이며 JSON 읽기와 검증은 별도 비용입니다.
7. 배열 자체의 공간은 O(N²)이고, 2차원 MAC의 누적 변수에 필요한 추가 공간은 O(1)입니다.
8. 1차원 변환도 O(N²) 시간과 추가 공간이 필요합니다.
9. 비교 표는 같은 입력과 반복 횟수를 사용하고 변환 시간을 측정 전에 제외했습니다.
10. 따라서 표는 이미 준비된 배열의 MAC 호출 비용 비교이며 전체 프로그램의 속도 향상을 뜻하지 않습니다.
11. 시간 측정은 perf_counter_ns로 함수 호출 구간만 재며 파일 읽기와 출력 시간을 제외합니다.
12. 파이썬 호출 비용, 운영체제 스케줄링, CPU 상태가 있어 실측 시간이 N² 비율과 정확히 같지는 않습니다.
13. 작은 배열에서는 타이머 자체의 비용도 비중이 크므로 반복 평균으로 흔들림을 줄였습니다.
14. 1차원 접근은 중첩 인덱싱을 줄이지만 항상 더 빠르다고 보장할 수는 없습니다.
15. 실제 NPU의 병렬 처리 성능이나 메모리 배치는 이 파이썬 측정으로 추정하지 않습니다.
